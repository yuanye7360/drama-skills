## 本文负责的做法

- `IMG-15` — 每条规格在元信息区声明它面向的**能力车道**，理由写成能力描述
  （身份一致性／宽幅电影感／产品感与文字渲染／以原图为底的最小改动／材质重生成／
  最细局部手术），不写工具名、模型名或服务参数；车道声明不进交付文本正文。
- `IMG-16` — 编辑永远从"以原图为底的最小改动"那一条车道开始；需要重建的画面不是
  编辑，是回去重新生成。

## 1. 为什么按能力分车道，而不是按工具名

同一句"帮我改一下这张图"，交给不同能力会得到完全不同的失败：以原图为底的能力会
保住构图但改不动细小结构；全局较脏、局部很强的能力能做最细的手术但会顺手重画整张；
材质重生成的能力能救糊掉的皮肤和布料，但**不能做定点修改**。

本套件不选购、不调用、不测试任何生成端，所以车道用**能力**命名。创作者在自己的
视觉方向／交付参数里把车道映射到实际在用的工具；工具换了，只改那张映射表，
不用重写任何一条 prompt。

**车道写在元信息区，不进交付文本。** 交付文本只含要拍出来的内容。

## 2. 六条车道

| 车道 | 能力特征 | 典型任务 |
|---|---|---|
| 身份一致 | 跨次生成锁住同一张脸／同一个身份 | 人物设定图、造型版本、需要跨镜认得出的人物帧 |
| 宽幅电影感 | 电影质感、自然颗粒、支持更宽画幅、可承接身份锁 | 地点空镜、建立帧、高压力风格帧、宽幅人物帧 |
| 产品感与文字 | 真实产品语境、物件形制稳定、画面文字渲染准确 | 道具板、带可读文字的物件 |
| 最小改动编辑 | **以原图为底**做后处理，改动之外像素级保持 | 绝大多数局部修改 |
| 材质重生成 | 把糊掉的皮肤、布料、表面重新生成出质感 | 只做材质通道，**不做定点修改** |
| 最细局部手术 | 局部极强、全局较脏（会顺手动到整张） | 前一条车道吃不下的极小局部 |

一个项目可以只用其中两三条。**没有映射到实际工具的车道就不要声明**，不为字段齐全
生成占位。

## 3. 生成车道的选择

- **人物与造型 → 身份一致车道。** 跨镜一致性由该车道的身份锁承担，散文只做加强
  （"三个画面里是同一个真人"）。**不要指望靠形容词把同一张脸写回来**。
- **地点与电影感空镜 → 宽幅电影感车道。** 需要更宽画幅时尤其如此：多数身份一致车道
  不支持最宽的画幅，这时把身份锁带进宽幅车道，而不是把宽幅需求塞回身份车道。
- **道具与产品感物件 → 产品感与文字车道。** 这是唯一一类默认不走生成主车道的资产：
  物件在产品语境下更容易保住形制与尺度，画面文字也更容易逐字落地。
- **风格帧（Lookdev）** 跟随它测试的轴：人物表现帧走身份一致车道，核心地点帧与
  高压力帧走宽幅电影感车道。见 [lookdev-frame.md](lookdev-frame.md)。

平台参数（画幅、分辨率、身份锁开关）在界面里设，不写进正文，见
[palette-light-and-register.md](palette-light-and-register.md) 第 6 节。

## 4. 编辑车道的固定顺序（`IMG-16`）

顺序是固定的，不是偏好：

1. **最小改动编辑**——每一次编辑都从这里开始。编辑 ＝ 对**原图**的后处理：原图是底，
   改动量最小。
2. **材质重生成**——只在"画面对、但材质糊"时使用。它的唯一职责是把糊掉的皮肤毛孔、
   布料织纹、地面脏污重新长出来。**永远不要把定点修改交给它**——它会重画。
3. **最细局部手术**——最后手段，只在第 1 条吃不下某个极小局部时用。它全局较脏，
   所以 **CHANGE 越小，结果越干净**。

三条之外还有一条判断：**需要重建的画面不是编辑，是回去重新生成。** 用编辑去重建一张
图，得到的既不是新图也不是原图，而且丢掉了原图可比较的价值。

创作者说"你改太多了"＝**你确实改太多了**：锁更多，改更少。这不是措辞问题。

## 5. 编辑车道的交付文本形状

生成 prompt 用自然散文；**编辑 prompt 是唯一使用 CAPS 区块的交付文本**，因为
"改什么／保留什么"必须被读成两个互斥清单：

    Edit the image: [一句话目标].

    CHANGE: [只有那一件事，写精确].

    PRESERVE EXACTLY:
    - [逐条列出必须完全不变的：脸、服装、道具、位置、墙面地面、机位、所有既有阴影]
    - Color grade, palette, contrast, grain, falloff

    ONLY CHANGE: [重述那一件事]. 100% identical otherwise.

- **一次只改一件事。** 多个不相干目标拆成多条。
- **最小 CHANGE、穷尽 PRESERVE。** preserve 集写不长，通常说明还没想清楚哪些东西
  会被顺手改掉。
- **移除必须配填补**："移除路灯" 要写成 "移除路灯，其后是连续的砖墙"。只写移除，
  空出来的地方会被自由发挥填满。
- 规格字段（target/hash/region、changes、preserve、continuity impact）见
  [edit-and-revision.md](edit-and-revision.md)；本节只规定交付文本的形状。

## 6. 换视角：必须逐个物件写出新排布

同一个地点换观察方向，是这条车道最容易翻车的任务。

- **最细局部手术车道**通常能较好地处理换视角，可作为默认路由；
- 走**最小改动编辑车道**时，必须**强迫说明新的物件排布，逐个物件写**：

      主视图里沙发在右边；这个反打视图里沙发在左边，
      原本在镜头后方的门现在出现在正前方，服务台从画面右前退到左后。

  不写清楚，几何会被打乱：模型会保留"沙发在右"的记忆，同时又转了机位。

换视角不改变地点身份，也不自动创造新 Location（`AST-03`）；它产出的是同一地点的新
View，地理由资产阶段拥有，见 [location-plate.md](location-plate.md)。

## 7. 失败征兆与检查

### 失败征兆

- 元信息区写了工具名、模型名或服务参数，或车道声明漏进了正文；
- 定点修改被交给材质重生成车道；
- 用编辑做重建（改完之后原图只剩构图还在）；
- CHANGE 很长、PRESERVE 很短；
- 只写移除、没写填补；
- 换视角时没有逐个物件写新排布；
- 靠散文描述追求跨镜身份一致，没有使用身份锁。

### 检查

1. **结构**：车道声明存在且在元信息区；编辑规格四问齐全；正文无平台参数与工具名。
2. **内容**：车道理由是能力描述而非工具偏好；编辑的 preserve 集覆盖真正会漂的事实。
3. **默认**：车道映射由创作者的交付参数决定；本阶段不替创作者选购工具，也不从一次
   观察把某条车道提升为通用定律。
