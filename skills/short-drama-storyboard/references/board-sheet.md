## 本文负责的做法

- `SHT-25` — 预览板是**提案**，不是边界权威：它的作画媒介故意不同于成片，标注只活在
  板层、永不进入交付帧，它可以提议镜头进展但不构成镜头数公式；正式镜头仍由原文落实与
  镜头表决定。
- `SHT-26` — 关键帧板是若干**已接受**关键帧的一种渲染：每格绑定一个已接受的镜头边界，
  格序等于来源顺序。它是一致性锚，不是首帧来源——交给视频生成的首帧仍逐镜渲染。

## 1. 先分清是哪一种板

两种板长得像，位置完全相反。选错会让整张板白做。

| | 预览板 | 关键帧板 |
|---|---|---|
| 在流程哪一层 | 镜头表**之前**：提案动作编舞与镜头进展 | 镜头表**之后**：渲染已接受的关键帧 |
| 作画媒介 | 故意不同于成片（粗铅笔、黑白、未完成） | 项目已接受的视觉方向 |
| 每格绑定 | 编舞节拍或提议的镜头，尚未有边界 | 一个已接受的镜头起始边界 |
| 标注箭头 | **要**，且要宣告图例 | 不要，它是渲染不是笔记 |
| 它买到什么 | 动量、轮廓可读性、镜头语言与升级曲线 | 跨格的光、色、材质与身份一致性 |
| 怎么拿它生视频 | 当**参考图**配文字 prompt，一次生成多镜（第 9 节） | 当**逐镜首帧的参考图**，首帧仍逐镜生成 |
| 能裁一格当首帧吗 | 不能，标注画在画面上 | 不能，分辨率与重生成结构不允许 |
| 记账 | 项目工作历史，不进交付包 | `keyframe-prompts.md` 里的一节 |

需要"这套动作到底怎么打、怎么拍"时做预览板；需要"这几镜的光色身份别互相漂"时做关键帧板。
一场戏两种都做是合理的，但不要指望一张板同时干两件事——粗铅笔黑白板锚不住色彩，
成片质感板承载不了满屏箭头。

## 2. 预览板：作画媒介故意不同于成片

预览板的作画媒介是**被选择的**，不是省事：

    粗糙的铅笔线条、最小细节、快速手势绘图的能量、简单的解剖结构、
    强烈的轮廓可读性；保持轻量、动态、未完成，像早期动作编舞预览

这个选择买到三件事：

1. **注意力落在动量与轮廓上**，而不是材质与皮肤。这一层要判断的是"这个姿势看得懂吗、
   身体的动量对不对"，材质细节只会掩盖答案。
2. **它不会被误当成 look 或首帧。** 一张成片质感的板会立刻引起"能不能直接用"的讨论；
   一张铅笔板不会。媒介本身就是边界声明。
3. **单格面积很小时仍然可读。** 12 格的每格只有整图十二分之一，粗线条与强轮廓是这个
   面积下唯一还能读出动作的画法。

因此预览板**不能**当一致性锚：它没有色、没有光、没有材质。它锚的是动作与镜头语言。
需要色光一致性时做关键帧板（第 9 节）。

## 3. 标注色彩系统（`SHT-25`）

预览板的价值一半在标注上——那是"轨迹"真正被看见的地方。图例必须在提示词里逐条宣告，
否则模型会画出颜色随机、含义不明的箭头：

| 颜色 | 含义 |
|---|---|
| 红色箭头 | 身体运动 |
| 蓝色箭头 | 相机运动 |
| 绿色标记 | 构图 / 布局笔记 |
| 橙色标记 | 光线方向 |
| 黄色标记 | 元素 / VFX / 能量效果 |
| 黑色文本 | 简短镜头笔记与面板标签 |

这套对应关系是 `taste_option`，项目可以自定；**但一经声明就固定**，同一项目里不换色义，
否则跨场的板互相矛盾而没人发现。

**标注只活在板层。** 它永不进入任何交付帧：逐镜关键帧提示词与视频提示词不得复制板上的
箭头、标签或面板编号——那些是给人读的笔记，执行端会把它们当成画面里应该出现的图形与
字符（同一条界线见
[production-shot-grammar.md](production-shot-grammar.md) 的交付文本边界）。板与帧的
关系是**板上的红箭头，在帧里改写成可测量的走位与朝向**（见
[spatial-lock.md](spatial-lock.md)）。

黑色文本的面板标签是画面内的字符，属于这张板自己的文字要求；它与资产的可读文字政策
无关，也不构成交付帧的文字义务。

### 每格底下一条注解带

把每格的标注写成格下方一条固定栏位的注解带（画面区之外），一格一条，六栏固定顺序。
它是这张板最可复用的部分——**六栏正好就是镜头表的字段**：

| 注解栏 | 例 | 对应的镜头字段 |
|---|---|---|
| RED | head down + finger fidget | 这一镜的身体动作 |
| BLUE | camera push forward | 运镜 |
| GREEN | visual weight (lower right) | 构图 |
| ORANGE | strong side light (sunset) | 光向 |
| YELLOW | dust particles in beam | 环境粒子 / 效果层 |
| LENS NOTE | establish oppression & isolation | 镜头目的 |

六格 × 六栏，镜头表就已经写完了——用画的。后续写 `shots.jsonl` 与关键帧时逐格读回这
六栏，不需要重新构思构图、运镜与光向；缺的只是把它们落成可测量的走位与准确的资产绑定
（见 [spatial-lock.md](spatial-lock.md)）。

栏位名与配色是 `taste_option`，项目可以自定；一经声明就固定。注解带放在画面区之外，
这样画面本身只被箭头影响，注解带不参与任何裁切。

## 4. 每格一行：内容 ＋ 镜头语言

预览板的每格用**一行**写完，不要展开成段：格号、这一格在做什么、以及用什么镜头语言拍。
镜头语言写可观察结果（长焦侧面轮廓、自上而下、极端低角、轨道环绕），不写毫米数——
与逐镜提示词同一套语汇，见视频提示词阶段的光学语言。

    1  空中飞跃斜踢的中途，已在运动中
    2  手部特写，掌扫切过空气
    3  轨道环绕全身的全景
    4  低角度冲击掌击
    5  长焦侧面轮廓旋转踢
    …

一行的长度限制是有用的：它逼迫每格只承担一个可读的动作与一种镜头语言。一格写成三句，
通常意味着那是两格。

**整张板共用的摄影语汇写在板级**，不逐格重复：手持能量、快速平移感、轨道移动、顶视、
侧面轮廓、激进特写、长焦压缩、极端低角、宽阔负空间、强烈视差。逐格只写它取用哪一种。

## 5. 进展轴：把升级写成跨格曲线

预览板最有效的结构装置：不逐格堆形容词，而是给一条**跨格的曲线**，说明某个量沿板递增。

    元素强度  早期格：微妙的风、尘土与压力线
              中期格：更强的石块碎片、地面涟漪与空气冲击波
              晚期格：受控的火焰轨迹与能量螺旋
              最终格：表演者仍在空中，最强的组合元素激增

同一写法可用于动作强度、身体压力、光的硬度、空间开阔度。它比逐格描述更稳，因为它给的是
**方向**而不是十二个互不相关的绝对值——十二个绝对值里只要有两个互相矛盾，整板的升级感
就塌了。

进展轴也是这一层能回答而后面各层回答不了的问题：升级是不是真的在升级，还是同一强度
重复十二次。

## 6. 直接从动作开始

    直接从动作开始。不要以平静站姿、准备镜头或缓慢介绍开始。
    第一格就已经在运动中。每一格都必须有可见的运动与身体动量。

这是首帧占位在板层的版本，理由相同：没有明确要求时，生成端会给一个"合理的开场"——
一个站定的准备姿势，然后把真正的动作挤到后面几格。板上浪费两格，等于这场戏的动作
预览少了六分之一。

## 7. 密度控制

12 格的每格面积很小，环境细节会直接吃掉轮廓可读性。环境写成**最小且有氛围**：

    高耸的石柱、磨损的地面、飘浮的香烟、悬挂的布料、刺眼的光束、
    空气中微弱的尘土、微妙的湿地面反射。不要让画面过于拥挤。

"不要让画面过于拥挤"这一句要显式写出来。它不是审美偏好——格数越多，模型越倾向于把每格
填满，而填满的代价正好是这张板唯一要保住的东西。

## 8. 预览板的负面清单

预览板是套件里少数**允许一小段负面清单**的交付文本，因为它不是交付帧，而且这些项都是
生成端会主动添加的东西：

    无时间戳。无对话。无额外角色。无敌人。无标志。无水印。

仍然不堆通用禁词（"不要变形、不要模糊、高质量"）。只写这张板确实会长出来的东西。

## 9. 拿板当参考喂视频：一次生成多镜（`SHT-25`）

板不只是给人看的。它可以**当这次视频生成的参考图**，配一段文字 prompt，一次生成一段
覆盖多个镜头的视频——格序就是镜序，格与格之间就是切点。

这在套件里已经有名字：**多镜交付容器**。规则照旧，不因为参考图是一张板就放松
（见视频提示词阶段的交付档案）：

- 切点只允许落在已接受的镜头边界上，不在格内偷切；
- 容器时长等于各成员镜头已接受时长之和；
- 每个成员镜头仍要能单独审查——一次生成不等于一个不可分的整体；
- 生成结果是**观察证据**，不是已接受产物：它不能回写镜头边界。

### 必须显式声明输出不是一张板

这是这条路唯一的新失败模式，而且它很贵：模型会把参考图的**形式**一起学过去，
生出"一张动起来的故事板"——画面里带着分格线、面板标签，甚至箭头跟着动。

所以文字 prompt 里要正向写清输出是什么：

    输出是连续的实拍式画面，整幅单一画面，没有分格、没有面板边框、
    没有面板标签、画面内没有箭头与标注文字。

参考图只提供动作进展、构图、运镜意图与光向；**板的版式、标注与文字一律不进入成片**。
这一条与"标注只活在板层"是同一件事，只是这里的板不是给人读，而是给模型读，所以要
把界线写进 prompt 而不是写在旁边。

顺带一条：板的作画媒介（铅笔、未完成）同样属于形式。若成片要的是项目已接受的视觉方向，
prompt 要显式声明成片的媒介与质感，不让参考图的铅笔感被当成风格要求继承过去。

## 10. 关键帧板：一次生成买到跨镜一致性（`SHT-26`）

与预览板相反，关键帧板用项目已接受的视觉方向作画，每格绑定一个**已接受**的镜头起始
边界，格序等于来源顺序。

它买到的不是省几次生成，而是**这几格彼此一致**：分开生成 N 张首帧，最贵的失败是它们的
光向、色调、空间与身份互相对不上，而那是后面每段影片接不起来的根源；同一次生成天然共享
这些。省的是返工。

两条硬边界：

- **不能当首帧。** 一板九格每格只有九分之一像素，裁边会带进相邻格的分隔线与透视残余；
  且板里坏一格，整板重生成会让另外八格一起变，一致性白付。
- **格数跟随已经选定的镜数，版式永不决定镜头数。** 这是既有"宫格只是人工比较界面，
  不是镜头数量公式"界线的又一个入口（见
  [coverage-audition.md](coverage-audition.md)），也最容易被绕过，因为"九格刚好"
  读起来像个理由。

分工固定：关键帧板作一致性锚与比稿，逐镜首帧作交付；后者可以把关键帧板当参考图，
借身份、光向与色彩关系，**不借构图**。坏一格时按代价排序：定点编辑 → 直接生成那一镜的
完整分辨率首帧 → 只有坏的是跨格共同事实（光向、造型、空间关系）时才整板重生成。

每格的正文仍按单帧规则写：一个能同时成立的瞬间，不含"先、再、最后"，不含表演变化过程或
运镜过程（见 [keyframe-craft.md](keyframe-craft.md)），并按
[performance-projection.md](performance-projection.md) 投影表演。

## 11. 提示词骨架与交付位置

**预览板**是项目工作历史，与 coverage audition 同类：它提议镜头进展，但不构成边界权威，
默认不进执行交付包。骨架：

    [板级：画幅、格数、版式；作画媒介的显式声明]。
    [一句话说明这是什么表演／动作，以及参考图只决定身份]。
    [直接从动作开始的声明]。
    动作进展：1 [内容 ＋ 镜头语言] / 2 … / N …
    [进展轴：早期／中期／晚期／最终格各自的强度]。
    [板级摄影语汇]。[环境最小化与密度控制]。
    [标注色彩系统图例]。[这张板的负面清单]。

**关键帧板**作为 `keyframe-prompts.md` 里的一节，不新增产物；元信息写覆盖镜头与边界
`hash`、版式、用途（一致性锚 / 比稿）、格间分隔与格号的处理方式。

格数、行列、媒介与标注配色都是 `taste_option`；预览板的标注边界与关键帧板每格绑定的
已接受边界是 `reviewed_invariant`。
